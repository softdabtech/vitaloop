## Cross-cutting rules for every stage above

- **No stage deploys without its "tests before deploy" passing first**, run against a non-production target (staging, once 2I repairs it — until then, a local/CI run or a carefully-scoped read-only check against a tagged prod account, per how Stage 1's live journey was conducted).
- **Every prod smoke verification uses the same tagging discipline established in Stage 1** (`AUDIT-TEST`/`vitaloop-audit-test+...` identifiers), never real user data.
- **Feature-flag stages (2B specifically) get an explicit "flag off, deploy, verify no-op, then flip" sub-sequence** — the deploy event and the behavior-change event are deliberately decoupled so a bad deploy and a bad *behavior* can be distinguished and rolled back independently.
- **No stage in this order requires a service restart beyond the normal deploy restart** (no nginx reload needed for any of 2A–2H; 2I explicitly includes the one nginx cleanup item, and even that is a stale unused route removal with zero live traffic, per Stage 1's finding that nothing calls it).
- **This order can be safely reshuffled for 2A/2A.5/2F, which have no dependencies on each other or on anything else** — they're listed in the sequence above only for narrative clarity, not because of a technical ordering constraint.
